Banking · INDUSTRY BLUEPRINT

Payment exception investigation desk

Reconcile payment evidence across ledgers, screening queues, and customer records while keeping release authority with bank operations.

Explore in the architecture studio

The business situation

Illustrative reference architecture. Validate requirements for your organization.

Illustrative architecture: A regional bank receives cross-border payments with mismatched beneficiary details. Operations must assemble a case before the settlement cutoff, but ledger status, customer instructions, and screening evidence arrive independently. This design assists investigation; it neither recommends investments nor autonomously releases funds.

Problem

A single conversational assistant can confuse a missing receipt with a failed payment. Retrying a release after a timeout can create duplicate financial effects. Evidence also crosses branch and customer confidentiality boundaries.

Why a multi-agent system?

Independent specialists can reconcile transaction facts, explain procedural requirements, and check evidence completeness in parallel. A deterministic case state machine owns deadlines, permissions, and payment identifiers; agents never invent their own authorization.

Intended outcome

The intended result is a reviewable operational decision with source evidence and explicit ownership. Measure case preparation effort and unresolved exceptions against the existing desk process. Success requires fewer unsupported claims without increasing erroneous release attempts; any business improvement remains a hypothesis until observed.

Architecture diagrams

Runtime flow

  1. 1

    Register exception

    Deduplicate the incoming event by transaction and exception version, then assign a settlement deadline and operations owner.

  2. 2

    Bind access

    Resolve branch, account, and case entitlements before fetching instructions or ledger evidence; missing authority suspends retrieval.

  3. 3

    Gather snapshots

    Run reconciliation and document retrieval concurrently, recording source timestamps, record versions, and unavailable dependencies in the evidence ledger.

  4. 4

    Compare facts

    Use deterministic amount and currency checks; let the agent explain discrepancies without converting uncertain text into booked facts.

  5. 5

    Assemble decision

    Present the unresolved checks, policy citations, and proposed operational action with the exact payment state the reviewer is approving.

  6. 6

    Commit and reconcile

    An authorized adapter rechecks current status and approval scope, submits once with a stable key, and reconciles any ambiguous response.

Failure recovery

Release acknowledgement disappears after submission.

Detect: Status query finds an ambiguous attempt associated with the original payment key.

Recover: Hold new submissions; reconcile ledger and gateway receipts before the operator decides whether another request is valid.

A policy citation refers to a superseded procedure.

Detect: The procedure version differs from the version effective at the review timestamp.

Recover: Invalidate the draft, retrieve the current procedure, and request a fresh decision for affected checks.

Security & decision boundaries

  • Keep release credentials outside every model and specialist process.
  • Require approval bound to transaction ID, amount, currency, and evidence version.
  • Enforce customer and branch access before retrieval and again before rendering citations.
  • Record screening disposition as an authoritative external fact with its source owner.
  • Redact account identifiers from telemetry while retaining protected correlation references.

Operational metrics

Measurement definitions, not promised improvements.

Investigation latency

Median and p95 time from exception ingestion to reviewer-ready case, separated from human queue time.

Evidence completeness

Cases containing every mandatory source reference divided by cases presented for approval.

Ambiguous action rate

Release attempts requiring reconciliation divided by all approved release attempts.

Reviewer correction rate

Reviewed drafts with material factual corrections divided by all reviewed drafts.

Rollout plan

Historical replay

Operations verifies representative exception classes and every proposed action against archived dispositions; no live writes occur.

Shadow investigations

Live drafts remain internal until evidence completeness and privacy tests meet bank-defined acceptance thresholds.

Controlled assistance

One operations queue enables approved adapter calls only after duplicate-submission and timeout-reconciliation exercises pass.

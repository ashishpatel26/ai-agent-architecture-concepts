74 — Hypothetical Document Embeddings (HyDE)

Generate a hypothetical relevant passage to improve retrieval alignment, then answer only from real retrieved evidence.

Concept overview

Hypothetical Document Embeddings, or HyDE, addresses the mismatch between a short query and the longer documents indexed by a dense retriever. A language model creates a plausible answer-like passage; an encoder embeds that hypothetical passage and uses it to search the real corpus. The generated text is a retrieval aid, not a factual source.

HyDE can help when a query lacks the vocabulary or structure found in relevant documents. It can also steer retrieval toward a fabricated assumption, especially for rare entities or ambiguous questions. Retaining the original query and comparing direct retrieval provides a useful control, while fusion can reduce dependence on one hypothetical generation.

Why it matters in production

Proof of concept

A prototype compares direct-query embeddings with HyDE on zero-shot retrieval examples and labels topic drift.

Production

Production constrains generation, excludes invented details from the final evidence set, and caps added model latency.

Enterprise scale

At scale, evaluate benefits by query class, cache safe hypothetical representations, and version the generator and embedding model together.

Architecture components

Hypothetical passage generator

Produces domain-shaped search text while preserving known query constraints.

Embedding encoder

Maps the generated passage into the same space as real documents.

Real document index

Returns actual source passages with provenance and authorization metadata.

Fusion controller

Optionally combines HyDE and direct-query candidates.

Evidence-only answer stage

Uses retrieved sources and excludes the hypothetical passage as authority.

Finding an unfamiliar failure mechanism

Materials science · Illustrative enterprise scenario, not a reported customer outcome.

Business situation

An engineering assistant searches a technical library for descriptions of a surface defect expressed in informal language.

The problem

The user’s short description shares few terms with the relevant materials reports.

Agent requirement

Improve retrieval vocabulary without asserting a diagnosis from generated text.

Architecture

HyDE generates a candidate technical description and combines its retrieved passages with direct-query results.

Runtime

  • The hypothetical passage introduces likely descriptive terminology.
  • The answer stage compares real reports and states only mechanisms supported by those sources.

Failure scenario

If the hypothetical text invents an alloy or operating condition, constraint validation rejects that retrieval branch.

Operational impact

Measure recall improvement, hypothetical drift, and added latency; success means finding better real evidence, not producing a convincing invented document.

Architecture tradeoffs

DecisionBenefitCost
Answer-like query representationCan bridge vocabulary mismatch.Adds generation cost and assumption risk.

Failure scenarios & recovery

Hypothesis narrows to wrong cause

Detect: Retrieved passages reflect an invented diagnosis.

Recover: Compare original constraints and diversify or discard the hypothesis.

Generated text leaks into citations

Detect: The final response cites content absent from the corpus.

Recover: Keep hypothetical text outside the evidence schema.

Common architecture mistakes

Treating HyDE as synthetic knowledge

Use it only to locate real evidence.

Adding unsupported entity details

Preserve unknowns and validate explicit constraints.

Applying it to every query

Enable it only on evaluated query classes.

When to choose this pattern

Choose it when

  • Use for short descriptive queries with vocabulary mismatch.
  • Use for zero-shot retrieval where relevance labels are scarce.
  • Use when added latency yields measured recall gains.

Avoid it when

  • Avoid exact identifier lookups already handled lexically.
  • Do not use hypotheses as factual evidence.
  • Avoid ambiguous high-impact questions without alignment checks.

Architecture checklist

  • Retain the original query.
  • Bound hypothetical passage length.
  • Protect explicit entities and constraints.
  • Use the corpus-compatible encoder.
  • Exclude hypotheses from cited evidence.
  • Evaluate against direct retrieval on the same questions.

## Reference approach

Primary documentation was checked in grouped searches covering agent orchestration and persistence, the pinned A2A protocol, access-control standards, prompt injection, evaluation frameworks, private networking, privacy tooling, governance, provenance, and reliability patterns. Lessons are original architectural synthesis; industry scenarios are illustrative designs and do not claim measured customer outcomes. References support concepts and implementation semantics, not fictional deployment claims.

The A2A lesson deliberately cites protocol version 0.3.0 so its named objects have an explicit version context. ISO/IEC 42001 discussion uses the public overview and does not claim a clause-level conformity assessment or certification. Retention requirements must be verified for the actual account, endpoint, feature, region, and agreement; no universal provider promise is asserted. Statistical watermark evidence is distinguished from signed provenance and factual truth. Audit integrity is distinguished from legal non-repudiation conclusions. Explanation prose is distinguished from faithful access to model internal reasoning.

Some legacy reliability article URLs redirected to generic pages during research. The backoff reference uses the official AWS PDF, and the idempotency reference uses the official EC2 API documentation instead. Current software details are intentionally kept at architectural semantics rather than copying potentially fragile API examples.
